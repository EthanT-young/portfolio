Personal Cloud Infrastructure

The Oracle Cloud instance that runs this website and a few other services, all behind one edge proxy.

2026 – Present Docker · Caddy · OCI · Linux Always Free tier

Overview

I set up and run a containerized hosting environment on an Oracle Cloud ARM instance. Caddy sits at the edge, serving this site and routing each subdomain to its service. Every service runs as its own Docker Compose project on a shared Docker network.

Problem

I wanted a place to host my own site and tools that stays up all the time and costs nothing. Oracle Cloud's Always Free tier includes an ARM compute instance, so everything here has to fit within that one machine's limits.

Approach

  • One entry point. Caddy is the only container that accepts traffic from the internet. Every other service sits behind it.
  • Automatic HTTPS. Caddy obtains and renews TLS certificates for each domain with no manual steps.
  • Independent services. Each service is its own Docker Compose project. I can update or restart one without touching the others.
  • Shared private network. The services publish no ports of their own. They share a Docker network, and Caddy reaches each one by container name.
  • No build step. Caddy serves one public/ folder. Changing a file there changes the site with no build or restart, and Caddy serves nothing outside that folder.
  • Low memory use. Ollama runs the language model on the instance itself. I configured it to unload the model after each response, which frees memory for the other services.

Results

  • The whole setup runs on one Always Free instance and costs nothing.
  • Adding a service takes a new Compose project, a DNS record and a few lines of Caddy configuration.

Stack
